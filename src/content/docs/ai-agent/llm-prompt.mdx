## LLM 是一台超強的「接下一個字」機器

LLM（Large Language Model，大型語言模型）讀過海量文字，學會了「看到前面這些字，下一個字最可能是什麼」。它能一路接下去，接出看起來像推理、寫程式、做分析的內容。

從這個本質可以推出三個非常實用的結論：

- **它不是資料庫。** 它不知道你們公司九月的營收是多少，除非你把數據給它（或給它查詢工具）。
- **它會一本正經地講錯。** 當它不知道答案時，仍然會接出「看起來合理」的文字，這叫幻覺（hallucination）。所以數字類的東西一定要讓它**用工具算**，而不是用腦袋猜。
- **你給的上下文決定品質。** 同一個模型，給的背景越清楚、要求越具體，答得越好。

## Token 和 Context Window：大腦的書桌

LLM 讀寫文字的單位叫 **token**，大約是一個英文單字的一部分，中文大約一個字就是一到兩個 token。計費也是按 token 算。

**Context window** 是模型一次能看到的 token 上限。所有東西——你的指令、對話歷史、工具說明、查回來的資料——都要擠在這張書桌上。

## 好 Prompt 的五個零件

| 零件 | 回答的問題 | 範例 |
|---|---|---|
| 角色 | 你是誰？ | 你是電商平台的資深數據分析師 |
| 任務 | 要做什麼？ | 根據下方數據，寫一份活動成效摘要 |
| 背景 | 需要知道什麼？ | 淨營收 = 營收 − 退款；活動成本是折扣與回饋的支出 |
| 規則 | 有什麼限制？ | 只用表格裡的數字，不要推測；不確定就說不確定 |
| 格式 | 長什麼樣子？ | 三個重點 + 一個風險，每點不超過 40 字 |

### 同一件事，兩種寫法

```text
# 寫法 A：模糊
幫我分析一下這個活動數據

# 寫法 B：五個零件齊全
你是電商平台的資深數據分析師。

任務：根據 <data> 裡的活動數據，寫一份給主管看的成效摘要。

背景：
- 淨營收 = 營收 − 退款
- ROI = (淨營收 − 活動成本) / 活動成本

規則：
- 只使用 <data> 裡的數字，不要自行推測或補數字
- 如果資料不足以下結論，直接寫「資料不足」

格式：
1. 三個關鍵發現（每點 40 字內，附數字）
2. 一個需要注意的風險

<data>
（貼上你的表格）
</data>
```

用 `<data>` 這類標籤把資料包起來，是個小技巧：讓模型清楚分辨「哪些是指令、哪些是資料」，[第 8 站](../eval-safety/)講安全時會再用到這個觀念。

### 再多兩招

- **給範例（few-shot）**：與其描述「我要的風格」，不如直接貼一份你滿意的舊報告當範例。
- **要結構化輸出**：要求「只輸出 JSON，欄位為 finding, number, risk」，程式就能直接讀取結果。這在 Agent 裡非常重要。

:::note[實務連結]
如果你在工作中寫過「指標口徑定義」或「常見 bug 清單」，那其實就是最高品質的「背景」和「規則」。很多分析師早就在做 prompt engineering，只是沒用這個名字叫它。
:::
